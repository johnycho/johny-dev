[diagram-design](https://github.com/cathrynlavery/diagram-design)은 "자연어로 요청하면 **에디토리얼 품질의 다이어그램**을 자가완결 HTML+SVG 한 파일로 그려 주는" 에이전트 스킬입니다(MIT, 2026-10 기준 깃허브 스타 약 5.5만). 이 글의 목적은 하나입니다 — <mark>그 출력을 이 블로그에 넣었을 때 **모바일·PC에서 깨지지 않고 반응형으로 잘 표시되는지** 실제로 확인하는 것입니다.</mark>

## diagram-design이란

Claude Code·Codex·Cursor 등 Agent Skill을 읽는 도구에 설치해, "내 앱 아키텍처(프론트·백엔드·DB·Redis) 그려 줘" 같은 자연어 요청으로 다이어그램을 만듭니다. 특징을 공식 소개 기준으로 요약하면 이렇습니다.

- **출력은 `.html` 한 파일** — SVG가 그 안에 인라인으로 들어간 자가완결 파일. 더블클릭하면 바로 열립니다.
- **다이어그램 44종** — 아키텍처·시퀀스·사분면·워터폴·상태·서비스 블루프린트 등.
- **Mermaid를 사용하지 않습니다** — 자체 레이아웃으로 그려, 그림자 없는 에디토리얼 스타일을 지향합니다.
- **브랜드 적용** — 사이트 URL을 주면 팔레트·폰트를 맞춰 줍니다.

즉 결과물은 **SVG**라서, 블로그에 넣는 방법은 Kroki로 만든 기존 다이어그램과 크게 다르지 않습니다.

## 블로그에 넣는 두 가지 방법

1. **인라인 SVG(권장)** — HTML 파일에서 `<svg>` 부분만 떼어 본문(컴포넌트)에 그대로 넣습니다. 본문으로 색인되고, 테마·폭을 사이트가 제어할 수 있습니다.
2. **iframe 임베드** — HTML 파일 전체를 iframe으로 띄웁니다. 간단하지만 본문 색인이 안 되고 높이 관리가 번거롭습니다.

<mark>출력이 `viewBox`를 가진 SVG라, **인라인으로 넣으면 기존 PlantUML/Kroki SVG와 동일하게 다룰 수 있습니다.**</mark>

## 핵심 — 반응형 모델

diagram-design 출력 HTML을 뜯어보면 반응형 처리가 분명합니다.

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
...
.frame { max-width: 1200px; width: 100%; }
.diagram-container { width: 100%; overflow-x: auto; }   /* 가로 스크롤 래퍼 */
svg { width: 100%; min-width: 760px; display: block; }   /* 이 폭 아래로는 안 줄임 */
...
<svg viewBox="0 0 1000 500" ...>
```

읽어 보면 동작이 이렇습니다.

- **PC** — `viewBox` 덕분에 프레임 폭(최대 1200px)까지 **유동적으로 확대**됩니다.
- **모바일** — `svg`에 `min-width`(예: 760px)가 걸려 있어, 화면이 그보다 좁아지면 **축소하지 않고** `overflow-x: auto` 래퍼 안에서 **가로 스크롤**로 보여 줍니다.

<mark>즉 "작은 화면에 맞춰 줄여 글자를 안 보이게 하는" 대신, **원래 크기를 유지하고 가로로 스크롤**해 가독성을 지키는 방식입니다.</mark> 이 블로그가 기존에 쓰던 Kroki SVG(“`max-width:100%`로 화면에 맞춰 축소”)와는 **반대 선택**입니다.

## 테스트 결과

- **블로그 활용 가능 여부** — 됩니다. 출력이 `viewBox`를 가진 인라인 SVG라, 컴포넌트로 감싸 그대로 넣으면 기존 다이어그램과 똑같이 관리됩니다.
- **깨짐 여부** — 안 깨집니다. `overflow-x: auto` 래퍼가 있으면 모바일에서 넘치거나 잘리지 않고 로컬 스크롤로 처리됩니다.
- **단, 반응형 철학이 다릅니다** — diagram-design은 **모바일에서 가로 스크롤**(가독성 우선), 이 블로그 기존 규칙은 **축소해 한눈에**(스크롤 없음)입니다. 둘 중 하나로 통일해야 합니다.
  - 기존 규칙처럼 **축소-투-핏**을 원하면, 넣을 때 `min-width`를 빼고 `max-width:100%`만 남기면 됩니다. 대신 폭이 넓은 다이어그램은 모바일에서 글자가 작아집니다.
  - 반대로 복잡해서 줄이면 못 읽을 다이어그램은 diagram-design 방식(가로 스크롤)이 낫습니다.

<mark>결론 — diagram-design 출력은 이 블로그에 **인라인 SVG로 문제없이 넣을 수 있고**, 모바일·PC 모두 안 깨집니다. 다만 "모바일에서 축소할지, 가로 스크롤할지"를 블로그 규칙으로 정해 일관되게 적용하는 게 좋습니다.</mark>
