# 표현·용어 순화 규칙

담백한 기술 문장을 위해 **구어적·비유적·AI스러운 표현 대신 일반적인 기술 용어**를 쓴다.
(톤 원칙 자체는 [blog-authoring.md](./blog-authoring.md) 2절 참고. 게시글·wiki 공통 적용.)

## 검사 방법 (필수)
글 작성·수정 후에는 **아래 표의 '지양' 좌열 전체**를 코드블록 밖 본문에서 대조한다. **즉석에서 떠오르는 일부 단어만 grep하지 말 것** — 그러면 최근 추가된 항목이 누락된다(실제로 그렇게 놓친 적 있음). 표 좌열을 통째로 alternation으로 묶어 한 번에 스캔하고, 걸린 항목을 권장 표현으로 고친 뒤 커밋한다. 이 전체 대조는 **커밋 전 필수**이며 [blog-review](../skills/blog-review/SKILL.md) 절차의 일부다.

**자주 놓치는 단어(반드시 별도 확인):** `축`(관점·기준 의미 — 표 헤더의 "축", "두/세 축", "같은 축"까지 전부), `갈래`, `죽다`·`뜨다`(의인화), `게다가`, `담다`, `큰 그림`, `저울질`, 정리/`<mark>` 불릿의 **평서체(~한다/~된다)**. 이 중 `축`은 표 헤더에도 자주 숨어 있으니 아래로 반드시 훑는다:
```
grep -rnoE '[가-힣0-9 ]*축[으로을이 ]|^\| *축 ' blog/ | grep -viE '단축|축소|축적|축약|압축|구축|건축|x축|y축|z축|회전축'
```

## 예외 — 문맥상 자연스러우면 허용

억지로 바꾸지 않는다: **기동**(시작보다 적합할 때), **덤프를 뜨다**, **정합성·파싱·안전장치가 깨지다**, **훌륭하다**.

## 그 외

- **용어 선택**: 어려운 번역어보다 개발자에게 익숙한 외래어·표준 용어 우선. 예: **배압 → 백프레셔(backpressure)**, **(배치) 건너뛰기 → 스킵(skip)**. 처음 나올 때만 영문 병기.
- **일관된 비유는 허용**: 개념 이해를 돕는 지속적 비유(예: GC=세차, 메모리=집/방, LLM=두뇌·손발)는 괜찮다 — 산발적·구어적 표현만 지양.
- **개수·항목 나열은 리스트로**: "A와 B로 나뉜다", "셋입니다 — A, B, C"처럼 **여러 항목을 한 문장에 늘어놓지 말고** 불릿 리스트로 표현한다. 각 항목은 **한 가지·두 가지·세 가지**로 센다(하나·둘·셋 단독 수사 지양).

## 새 항목 추가 시 (필수)
사용자가 표현·문장을 지적하면(명시적으로 "규칙 반영"이라 하지 않아도), 실제 글을 고친 뒤 **두 규칙 파일을 모두 검토해 해당하는 곳에 반드시 반영**한다 — 이건 선택이 아니라 필수 단계다.

**규칙을 새로 추가·수정했으면, 그 규칙으로 기존 글에 위반이 남지 않도록 [`blog-polishing` 스킬](../skills/blog-polishing/SKILL.md)(`/blog-polishing`)을 실행해 전체(또는 관련) 블로그를 반드시 스윕한다.** 규칙만 늘리고 기존 글을 방치하지 않는다.

- **개별 단어 치환**(A라는 낱말 → B)이면 → **이 파일(word-choice.md)** 표에 한 행 추가.
- **문장·구조·톤·주체·형식**(모호함·나열식·말투·오해 소지·주체 생략·표/그림 정합 등)이면 → **[phrasing-style.md](./phrasing-style.md)** 표에 한 행 추가.
- 애매하면 **둘 다** 검토하고, 성격에 맞는 쪽(때로 양쪽)에 넣는다. "단어만 고치고 규칙은 안 넣기"는 금지.
