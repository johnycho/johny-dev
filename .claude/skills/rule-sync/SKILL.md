# 규칙 동기화 스킬 (커밋 전 필수)

작업 중 받은 피드백을 **고치기만 하고 규칙에 남기지 않으면** 다음 글에서 같은 지적이 반복된다. 이 스킬은 커밋 직전에 피드백과 규칙을 대조해 빠진 것을 채우고, 새 규칙을 블로그 전체에 적용한다.

> 실제 사례: "튀는"은 그림 라벨에서만 고치고 규칙에 넣지 않아 핫스팟 글에 12곳이 그대로 남았다. "담다", "풀리다"는 규칙에 기본형만 있어 "담은", "풀립니다"를 스캔이 잡지 못했다. 그림(```svg) 안 라벨은 스캔 대상이 아니어서 "묶음", "꽉 찬"이 남았다.

## 언제 실행하나
- **커밋 요청을 받으면 커밋 전에 항상** 실행한다(변경이 글, 그림, 규칙 어느 것이든).
- 사용자가 "규칙 반영 필요한지 확인해줘"라고 할 때.

> **hook으로 강제된다.** 커밋 명령 직전 [`require-rule-sync.sh`](../../hooks/require-rule-sync.sh)가 완료 표시를 확인해, 없거나 그 뒤에 파일이 바뀌었으면 커밋을 막는다. 블로그 전체는 [`require-polishing.sh`](../../hooks/require-polishing.sh)가 폴리싱 스캔으로 확인한다. **막히면 임의로 갱신하지 않는다.** 갱신안을 사용자에게 보여 주고 확인을 받은 뒤 반영하고, 커밋을 다시 시도한다.

## 절차

1. **피드백 수집**: 마지막 커밋 이후 사용자가 지적한 것을 모두 목록으로 만든다.
   - 단어: "X 지양어로", "X 말고 다른 표현"
   - 문장: "이해 안 가", "표현 다듬어", "너무 구어체", "부자연스러워"
   - 구조와 시각: "텍스트 위주", "그림으로", "SVG로", 라벨 형식(예: Y/N)
   - 작업 방식: 커밋, 언어, 절차에 대한 요청

2. **반영 위치 분류**: 각 항목을 아래 중 하나 이상에 대응시킨다.

   | 피드백 종류 | 반영 위치 |
   |---|---|
   | 개별 단어, 활용형 | [word-choice.md](../../wiki/word-choice.md) |
   | 문장 구조, 톤, 연결, 표 셀 표현 | [phrasing-style.md](../../wiki/phrasing-style.md) |
   | 글 구성, 시각 자료, 실무 예시, ASCII 금지 | [blog-authoring.md](../../wiki/blog-authoring.md) |
   | 그림 형식(라벨, 폭, 색, 분기 표기) | [diagram-svg](../diagram-svg/SKILL.md) |
   | 기계로 잡을 수 있는 검사 | [scan-polishing.py](../blog-polishing/scan-polishing.py) |
   | 리뷰 점검 항목 | [blog-review](../blog-review/SKILL.md) 체크리스트 |
   | 작업 절차, 커밋 방식 | 이 스킬, [CLAUDE.md](../../../CLAUDE.md), [.claude/README.md](../../README.md) |

3. **이미 반영됐는지 확인**: 규칙 파일을 grep하고, **스캔이 실제로 잡는지 시험한다.** 규칙에 기본형만 있으면 활용형을 놓친다.
   ```bash
   printf '지적받은 원문 문장\n' > <scratchpad>/t.mdx
   python3 .claude/skills/blog-polishing/scan-polishing.py <scratchpad>/t.mdx
   ```
   - 잡히지 않으면 좌열에 활용형(예: 풀립니다, 풀려, 안 풀려)을 추가한다.
   - 그림 라벨에서 받은 지적이면 ```svg 블록 안의 `<text>`나 ```plantuml 블록의 따옴표 라벨로 넣어 시험한다.

4. **갱신안 확인 받기**: 추가, 수정할 규칙과 블로그 전체 적용 범위(바꿀 곳 수, 대표 예시, 그대로 둘 문맥)를 사용자에게 보여 주고 **확인을 받는다.** 확인 없이 규칙이나 글을 바꾸지 않는다. 갱신할 것이 없으면 그 사실을 알리고 확인받는다.

5. **규칙 추가, 수정**(확인받은 대로):
   - 새 행의 **대체어가 이미 지양어 좌열에 있지 않은지** 확인한다(지양어를 지양어로 바꾸지 않는다).
   - 뜻이 여러 가지인 단어(주다, 잡다, 끊다, 나다)는 **바꿀 문맥과 그대로 둘 문맥을 함께 적는다**(예: 영향을 주다, 주고받다는 무관).
   - 문장 규칙은 지적받은 원문과 고친 문장을 예시로 넣는다.

6. **오탐 점검**: 블로그 전체를 스캔해 새 표면형이 무관한 단어를 대량으로 잡는지 본다(예: "나면"이 "끝나면", "지나면"을 잡음). 오탐이 많으면 좌열을 구체적인 형태로 좁히거나(장애가 나면, 예외가 나면), 스크립트의 `MASK`에 무관 단어를 추가한다.
   ```bash
   python3 .claude/skills/blog-polishing/scan-polishing.py blog/*.mdx | grep -E '\[(새 표면형)\]'
   ```

7. **블로그 전체 적용(스윕)**: 새 규칙으로 걸리는 곳을 **문맥에 맞는 대체어로** 고친다.
   - 본문, 표, alt, 그림 라벨(```svg 블록과 `static/img/c4/*.svg` 파일을 함께), PlantUML 원본(고친 뒤 Kroki로 다시 렌더)까지 포함한다.
   - 코드 식별자, 인용 원문은 건드리지 않는다.
   - 제목을 바꾸면 그 글로 가는 링크 문구도 함께 바꾼다.

8. **검증**:
   - `scan-polishing.py`로 새 표면형 0건(남은 것은 예외 문맥만) 확인
   - 그림을 고쳤으면 SVG XML 검증, 글 속 ```svg 코드와 파일 일치 확인
   - `npm run build` 통과

9. **완료 표시**: 모든 수정과 검증이 끝난 뒤 마지막에 실행한다. 이 뒤에 파일을 고치면 다시 막힌다.
   ```bash
   bash .claude/skills/rule-sync/mark-done.sh
   ```

10. **보고 후 커밋**: 사용자에게 아래를 짧게 알리고 커밋한다(커밋은 [git 계정 정책](../../wiki/git-account.md)대로 johnycho).
   - 추가, 수정한 규칙(파일별)
   - 스윕으로 고친 글 수와 대표 예시
   - 일부러 그대로 둔 문맥과 판단이 필요한 항목(예: 글의 핵심 용어라 바꾸면 제목까지 바뀌는 경우)

## 하지 않는 것
- 피드백을 그 자리에서 고치기만 하고 규칙에 남기지 않은 채 커밋하지 않는다.
- 규칙 파일만 고치고 기존 글 스윕을 생략하지 않는다.
- 사용자 확인 없이 규칙 파일이나 글을 바꾸지 않는다(판단이 갈리는 대량 변경은 특히).
