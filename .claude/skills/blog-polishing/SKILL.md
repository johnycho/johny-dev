# 블로그 다듬기 스킬 (규칙 기준 표현·문장 수정)

블로그 글의 표현을 johny-dev 규칙에 맞게 **직접 고친다**. 규칙은 두 파일이 **단일 진실 원천(SSOT)** 이며, 이 스킬은 규칙을 복제하지 않고 **매번 그 파일을 읽어** 기준으로 삼는다.

## 단일 진실 원천 (SSOT) — 매번 읽는다
- **단어 규칙**: [../../wiki/word-choice.md](../../wiki/word-choice.md) — 지양 → 권장 단어 표 + 예외. (표현을 새로 바꾸면 여기에 행 추가)
- **문장 규칙**: [../../wiki/phrasing-style.md](../../wiki/phrasing-style.md) — 모호함·모순·문장 조각·근거 링크·보충 노트·문체·주체·나열식·표방향·1인칭 등 문장/구조 패턴.
- 톤·MDX·볼드 렌더 등 형식 규칙: [../../wiki/blog-authoring.md](../../wiki/blog-authoring.md).

> 이 세 파일이 기준이다. 스킬 본문에 규칙을 옮겨 적지 말고, **작업할 때마다 위 파일을 열어 최신 표를 그대로 적용**한다(규칙은 자주 갱신된다).

## 절차

1. **대상 확정**: 다듬을 글(경로/슬러그)을 정한다. 안 주면 방금 작성/수정한 글 또는 `git status`의 변경된 `blog/*.mdx`. 여러 개면 사용자에게 확인.

2. **SSOT 로드**: `word-choice.md`와 `phrasing-style.md`를 **전문 읽는다**(매번 최신본을 다시 읽는다). 각 파일의 "검사 방법(필수)" 절차를 그대로 따른다.

3. **자동 스캔(단어) — 규칙 전체 기준**: word-choice 표의 **'지양' 좌열 전체(맨 위 오래된 항목부터 맨 아래 최신 항목까지 전부)**를 코드블록·다이어그램(plantuml/mermaid) **밖 본문**에서 대조한다. **"이번에 추가된 최신 규칙만" 보지 말 것** — 전체 폴리싱은 표 전체를 기준으로 한다. 즉석에서 떠오르는 일부만 grep하지 말고 **좌열을 통째로** 훑는다. 특히 **자주 놓치는 단어**(`축`은 표 헤더까지, `갈래`·`죽다`·`뜨다`·`게다가`·`담다`·`큰 그림` 등)와 word-choice "검사 방법"의 grep 레시피를 반드시 돌린다. 괄호 안 **예외**(헷갈리다·공짜·담당·감을 잡다·되돌리다(롤백) 등)는 건드리지 않는다.

4. **판단 스캔(문장)**: phrasing-style **규칙 목록 전체(#1~)** 를 체크리스트로 처음부터 끝까지 훑어, 각 패턴에 걸리는 문장을 찾는다. 대표: `<mark>`·정리 불릿의 **평서체(~한다/~된다) → 존댓말** 통일, 모호한 정성 표현 구체화, 주체 모호(남이/자동 재시도 오해)·1인칭("내가 …") 제거, 나열식 → 리스트, 표·그림 방향 일치.

5. **수정 적용**: 코드블록·다이어그램 내부 텍스트는 **절대 건드리지 않고**, 의미는 보존한 채 표현만 고친다. 문맥에 맞는 권장어를 고른다(같은 지양어라도 문맥별로 대체어가 다름).
   - 규모가 크면(여러 글 일괄) 배치로 나눠 **병렬 서브에이전트**로 고쳐도 된다(파일이 겹치지 않게 배치를 나눈다).

6. **새 규칙 반영(필수)**: 사용자가 새 표현을 지적했으면, 고친 뒤 **개별 단어는 word-choice.md, 문장·구조·톤·주체·형식은 phrasing-style.md** 표에 한 행 추가한다. 애매하면 둘 다 검토(때로 양쪽). "고치기만 하고 규칙에 안 남기기"는 금지.

7. **검증**: `npm run build`로 MDX 컴파일·내부 링크 확인. 볼드 렌더 깨짐(`grep -rnoE '[+%>)\]"'"'"'][*][*][가-힣]' blog/`)도 훑는다.

## 커밋
- 커밋·푸시는 [git 계정 정책](../../wiki/git-account.md)에 따라 **johnycho** 계정으로. 사용자가 명시적으로 요청할 때만.

## blog-review와의 차이
- **blog-review**: 규칙 위반을 **찾아 리포트**(기본은 수정 안 함).
- **blog-polishing**: 규칙 기준으로 **실제로 고침**. 리포트가 아니라 수정 결과와 변경 목록을 남긴다.
